# TDD — 감잡아 테스트 주도 개발 계획

> 상태: 초안 v0.2 (2시간 개발 기준). 원칙: **실패하는 테스트 먼저 → 최소 구현 → 리팩터링**. 외부 서비스(Copilot SDK, 날씨)는 테스트에서 가짜/목으로 대체한다. 2시간 P0 범위에서는 아래 **P0 필수 테스트**만 자동화하고, 나머지는 P1로 둔다.

**P0 필수 테스트(pytest):** 정책 필터(농약 패턴), 출처 ID 서버 검증, 승인 멱등·동시 승인, 세션 격리, 속도/길이 제한, 모델 장애 처리. E2E는 배포 후 수동 스모크 1회로 대체.

## 1. 테스트 전략
| 계층 | 도구 (제안) | 대상 | 우선순위 |
|---|---|---|:---:|
| 단위 | pytest | 도구 함수, 스키마 검증, 정책 필터 | P0 |
| 에이전트 | pytest + 가짜 모델 클라이언트 | 도구 호출 순서, 승인 흐름, 정책 준수 | P0 |
| API 통합 | pytest + httpx (FastAPI TestClient) + 인메모리 저장소 | 엔드포인트, SSE 스트림, 오류 | P0 |
| 배포 후 스모크 | curl/수동 | 배포 URL에서 `/api/health`, 데모 흐름(실제 모델 응답) | P0 |
| 프런트 | Vitest + Testing Library | 컴포넌트, 접근성 속성 | P2 |
| E2E | Playwright | 데모 과원 핵심 흐름 | P1 |

## 2. 우선순위별 테스트 케이스

### F1 데모 과원
- `GET /api/farms/demo` 가 인증 없이 200과 데모 과원을 반환한다.
- (P1, F5) 필수 필드 누락·잘못된 식재 연도는 422를 반환한다.

### F2 오늘의 할 일
- 제안 항목마다 `reason`, `sources(≥1)`, `ai_generated=true` 가 존재하고, 출처 ID는 실제 검색 결과에 있는 것만 허용된다 (지어낸 ID 거부).
- 지식에 근거가 없는 내용은 제안이 아니라 "확인 필요" 안내로 분리된다.
- (P1) 날씨 도구 실패 시 응답에 "날씨 정보 없음"이 포함되고 날씨 근거 제안은 제외된다.
- 측정되지 않은 값(예: 토양 수분)을 사실로 단정하지 않는다 (가짜 모델이 단정 출력 → 필터가 차단/수정).

### F3 채팅 스트리밍
- SSE가 `status`/`tool_call` 이벤트 후 검사 통과한 최종 `message`와 `done` 을 전달한다 (도구 호출이 본문보다 먼저 올 수 있음).
- 정책 검사를 통과하지 못한 본문은 클라이언트로 전달되지 않는다.
- 모델 오류 시 `error` 이벤트와 재시도 가능한 상태 메시지가 전달된다.
- 길이 제한 초과 입력은 거부된다.

### F4 캘린더·승인
- `propose_calendar_event` 는 `Proposal(pending)` 만 생성하고 `CalendarEvent` 를 생성하지 않는다.
- `approve` 후에만 `CalendarEvent` 가 저장된다; `reject` 시 저장되지 않는다.
- 만료/존재하지 않는 제안 승인은 404/409.

### 세션 격리·승인
- 세션 A의 제안/일정을 세션 B가 조회·승인하면 403/404.
- 같은 제안을 두 번(동시 포함) 승인해도 일정은 1개다.
- 도구 허용 목록 밖(셸·파일·URL) 요청은 거부된다.

### F6 기록 (P1)
- 작업/증상/수확 기록 CRUD, 날짜·수량 검증.
- 최근 기록이 `get_farm_context` 결과에 포함된다.

### 책임 있는 AI / 보안
- 농약 제품명·희석 배수·사용량 패턴이 응답에 포함되면 차단/대체 문구로 변환된다.
- (P1) 지식 문서/사용자 메모에 "이전 지시를 무시하라" 류 문구가 있어도 도구 호출·정책이 변하지 않는다 (인젝션 회귀 테스트). P0에서는 정책 문구로만 대응.
- 모든 AI 출력에 "AI 생성" 라벨이 UI에 렌더링된다.
- 응답·로그에 비밀 값이 포함되지 않는다.

### UX (P1/P2)
- 주요 컨트롤 레이블·키보드 포커스, 로딩·오류·빈 상태, 모바일 뷰포트(390px). axe 자동 검사는 P2.

### 수동 스모크 (배포 후, P0)
1. 데모 과원 시작 → 오늘의 할 일 표시.
2. 채팅 질문 → 상태 이벤트 + 최종 답변 + 출처 표시.
3. 일정 제안 승인 → 캘린더에 표시.
4. (P1, Playwright 자동화) 작업 완료 기록 → 목록 반영.

## 3. 개발 순서 (Red → Green)
1. 스키마/모델 + 정책 필터 단위 테스트 → 구현.
2. 도구 2종(`search_knowledge`, `propose_calendar_event`) 단위 테스트 → 구현.
3. 가짜 모델로 에이전트 테스트 → Agent Framework/Copilot SDK 연결.
4. API 통합 테스트 → 엔드포인트.
5. UI 구현 → 배포 후 수동 스모크.

## 6. 완료 정의 (DoD)
- P0 pytest 전부 통과, 배포 URL에서 수동 스모크 통과.
- 배포 URL에서 로그인 없이 **실제 모델 응답 + 도구 호출 1회 + 승인·조회**를 수동으로 확인 (가짜 모델 테스트만으로는 필수 기술 활용을 증명할 수 없음).
- 제출 전 `PRD.md`/`TRD.md` 를 저장소 루트로 이동/복사.
- 제출 커밋 해시와 배포 버전 일치 확인.
