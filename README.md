# 감잡아

청도반시 초보 농부를 위한 과원 수첩입니다. 기존 데모→오늘의 할 일→질문→일정 승인 흐름에 직접 등록, 작업·증상·수확 기록, 선택적 날씨, 영속 저장을 추가했습니다.

**2026-11-05: P1 구현 파일 작성 완료, 실행 검증 대기.** 기존 P0 테스트 41개는 유지했습니다. 이번 환경에서 Python·린트 실행 파일이 접근 거부되어 pytest·린트를 실행하지 못했습니다. JS 구문 및 변경 공백 검사는 통과했습니다. E2E는 작성만 했습니다. 설치·네트워크·배포·commit/push는 수행하지 않았습니다.

## 구조

- backend/app/: API, 검증, 정책, 서비스, 저장소 계약과 인메모리/Cosmos 어댑터, 날씨, 관측성.
- backend/agents/, backend/tools/: 기존 실행 연결, 가짜 응답, 읽기 조회와 승인 대기 제안.
- backend/tests/: 기존 회귀 테스트와 P1 API·날씨·공통 저장소 계약 테스트.
- frontend/: 기존 화면 유지. 등록 폼, 기록 폼·목록, 날씨 표시만 추가.
- data/knowledge/: 기존 확인 필요 자료 6개 유지.
- infra/: 기존 호스팅에 Cosmos serverless, Key Vault, 관리 ID·RBAC, Application Insights 추가.
- e2e/: 합성 자료 전용 서버와 Playwright 흐름 1개.
- references/: 현재 요구·설계·검증 문서. 루트 PRD/TRD도 동기화.

## 로컬 명령

이미 준비된 Python 3.12 환경에서 저장소 루트를 기준으로 실행합니다. 이번 작업에서 패키지는 설치하지 않았습니다.

```powershell
$env:GAMJABA_MODEL = 'fake'
$env:GAMJABA_STORE = 'memory'
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --workers 1 --no-proxy-headers --no-access-log
.\.venv\Scripts\python.exe -m pytest backend/tests -q
.\.venv\Scripts\python.exe -m ruff check backend e2e/server.py
node --check frontend/app.js
```

http://127.0.0.1:8000에서 데모를 열거나 과원을 등록합니다. 가짜 응답 모드는 화면에 명시하며 실제 연결 실패 시 자동 전환하지 않습니다. 실제 실행 연결의 기존 인증 환경변수 계약을 유지합니다. .env는 자동 로드하지 않습니다.

## API와 입력

모든 API는 UUID 형식 X-Session-Id 헤더가 필요합니다. 로그인 대신 쓰는 임시 접근 키이므로 공유하지 않습니다.

| 메서드 | 경로 | 동작 |
| --- | --- | --- |
| GET | /api/health, /api/farms/demo | 상태·데모 |
| POST | /api/farms | 직접 등록, 201 |
| GET | /api/farms/{id} | 등록 과원 복원·세션 확인 |
| GET | /api/farms/{id}/today, /calendar | 할 일·일정 |
| POST | /api/farms/{id}/chat | 질문, 검사 후 SSE |
| POST | /api/proposals/{id}/approve 또는 /reject | 멱등 승인·거절 |
| GET/POST | /api/farms/{id}/logs | 기록 목록·추가(201) |
| PUT/DELETE | /api/farms/{id}/logs/{logId} | 전체 필드 교체·삭제(204) |
| GET | /api/farms/{id}/weather?days=3 | 1~7일 예보, 실패도 없음 응답 |

등록 필수 필드: name·region(1~80자), cultivar(청도반시), plantedYear(정수, 1900~서울 기준 올해), areaM2(양수, 최대 10,000,000).

기록 필수 필드: type(work/symptom/harvest), date(YYYY-MM-DD, 1900년부터 서울 기준 오늘), note(1~2,000자). 수확에만 amount(양수 kg, 최대 10,000,000)가 필수이며 다른 종류에는 넣지 않습니다. 공백·비유한 수·불리언 수치·알 수 없는 필드는 거부합니다.

검증 오류는 422, 다른 세션의 객체는 404, 만료·상태 충돌은 409입니다. 기존 본문 16KiB·속도 제한을 유지합니다. 화면은 기록 추가·목록을 제공하고 수정·삭제는 API로 제공합니다.

브라우저는 마지막 등록 과원의 ID만 보관해 새로고침 후 같은 세션으로 다시 불러옵니다. 메모 원문을 브라우저 저장소에 따로 저장하지 않습니다. 인메모리 서버 재시작이나 세션 만료로 과원이 없어지면 다시 시작 안내를 표시합니다.

## 저장소와 캐시

기본 GAMJABA_STORE=memory는 외부 DB 없이 기존 인메모리를 사용합니다. 유휴 세션 TTL 2시간, 제안 TTL 30분, 최대 세션 1,000개, 등록 과원 20개, 과원당 기록 200개·제안 100개입니다. 최근 대화 4턴은 과원별로 격리합니다.

GAMJABA_STORE=cosmos 선택 시 azure-cosmos를 지연 로드합니다.

| 환경변수 | 용도 |
| --- | --- |
| COSMOS_ENDPOINT | 필수 HTTPS 계정 주소 |
| COSMOS_DATABASE / COSMOS_CONTAINER | 기본 gamjaba / state |
| AZURE_CLIENT_ID | 사용자 할당 관리 ID |
| COSMOS_KEY | 선택적 로컬 호환용 키. 배포는 키 인증 비활성 |

컨테이너는 Bicep에서 만들며 앱은 자동 생성하지 않습니다. 파티션 키는 /farmId입니다. 실제 과원 ID 파티션의 세션·세대별 단일 문서에 과원·기록·제안·일정·캐시를 보관합니다. ETag 조건부 교체로 승인 상태·일정 삽입·캐시 버전 증가를 원자적으로 반영합니다. 409/412는 재조회 후 최대 12회 재시도합니다. 응답 유실 후 재승인도 같은 일정입니다.

예약 파티션의 작은 디렉터리에 세션 만료·세대·과원 ID만 저장합니다. 등록은 과원 문서를 먼저 만들고 디렉터리에 연결합니다. 중간 실패의 고아 문서는 접근 불가이며 TTL로 정리됩니다. 활성 세션 접근 시 소유 과원의 물리 TTL을 갱신합니다. **논리 접근 만료는 유휴 2시간**, 과원 문서 물리 TTL은 갱신 여유를 둔 4시간입니다. 만료 디렉터리 항목은 다음 접근에 정리하며 같은 세션 ID의 새 세대가 이전 데이터에 접근하지 못합니다. 문서 1.9MB 상한과 단일 디렉터리는 소규모 데모용 제한입니다.

캐시는 세션·과원·서울 날짜 기준입니다. 기록 추가·교체·삭제와 승인 시 해당 과원 캐시를 비우고 버전을 증가시킵니다. 생성 시작 버전이 달라지면 오래된 결과를 다시 캐시하지 않습니다. 최근 기록 30개와 승인 일정이 생성 문맥에 들어갑니다. 오늘 work 메모가 작업 제목과 정확히 같거나 이미 오늘 승인한 제목이면 재제안에서 제외합니다. 자유 메모 의미만으로 완료를 단정하지 않습니다.

**workers=1, replica=1 유지:** 인메모리는 저장·세션이 프로세스 내부이므로 필수입니다. Cosmos는 재시작 복구와 조건부 쓰기를 지원하지만 요청 제한·동시 생성 한도·동일 요청 합치기는 아직 프로세스 내부입니다. 이를 공유화하기 전 Cosmos도 replica 1로 유지합니다.

## 날씨·안전·관측성

WEATHER_API_KEY가 없으면 네트워크 없이 날씨 정보 없음을 반환합니다. 키가 있으면 고정 HTTPS 예보 제공 경로를 호출합니다. 지역·일수 인터페이스를 정상·실패·지연 가짜 클라이언트로 시험합니다. 기본 타임아웃 3초, 잘못된 응답·연결 실패·지연 모두 없음 처리합니다. 실제 계정 요금제·한글 지역 해석·응답 호환성은 미검증입니다.

예보는 검증된 날짜·숫자만 표시하고 현장 측정과 구분합니다. 날씨가 없으면 이를 근거로 단정하는 답변·작업·일정을 보수적으로 차단합니다. 패턴 검사는 완전한 의미 검증이 아닙니다. 사용자 기록과 외부 자료는 신뢰하지 않는 데이터이며 조회 기능에는 저장소를 노출하지 않습니다. 진행 이벤트에 내부 호출 이름·인자·원문을 넣지 않습니다.

APPLICATIONINSIGHTS_CONNECTION_STRING이 있을 때만 OpenTelemetry 추적을 등록합니다. 없으면 관련 패키지나 전송기를 초기화하지 않습니다. 경로 템플릿·HTTP 메서드·상태·시간만 보내며 메모·질문·세션 ID·쿼리·전체 URL·예외 메시지·인증값은 수집하지 않습니다.

## 인프라·남은 검증

Bicep은 Cosmos serverless, Key Vault, 사용자 할당 관리 ID, ACR 읽기·비밀 읽기·Cosmos 데이터 권한, Application Insights를 추가합니다. 토큰·선택 날씨 키·관측성 연결 문자열은 Key Vault 참조로 주입합니다. ACR 관리자 키와 배포 Cosmos 키 인증을 제거했습니다. 기본 storageMode=memory이며 cosmos 매개변수로 선택합니다.

향후 명령은 az bicep build --file infra/main.bicep 및 azd up입니다. 이번에는 실행하지 않았습니다. Bicep 구문·리소스 API·RBAC 전파·관리 ID·새 패키지 조합은 검증 대기입니다. 배포 주체에 리소스 생성·역할 할당·비밀 등록 권한이 필요합니다. 비밀을 저장소나 로컬 배포 설정에 기록하지 않습니다.

초기 이미지 포트는 80, 실제 앱은 8000입니다. 실제 containerImage로 재프로비저닝하여 ingress·프로브도 전환해야 합니다. 이미지 교체만으로 포트가 자동 변경된다고 가정하지 않습니다. 신뢰 가능한 프록시 범위·네트워크 경계·예산 알림도 확인해야 합니다.

## 테스트

P1 pytest는 등록 검증, 기록 CRUD, 세션·과원 격리, 읽기 경계, 캐시 버전, 날씨 실패, 승인 경쟁·TTL·재시작을 검사하도록 작성했습니다. 저장소 계약은 인메모리·가짜 Cosmos 양쪽에 동일 적용하며 실제 DB는 호출하지 않습니다.

E2E는 e2e/flow.spec.js 1개입니다. 이미 준비된 환경에서 e2e 디렉터리의 npm test로 실행합니다. Windows에서는 E2E_SERVER_COMMAND에 저장소 루트 기준 Python 서버 명령을 지정할 수 있습니다. 전용 서버만 합성 검토 자료를 사용합니다. 이번 작업에서는 패키지·브라우저 설치나 E2E 실행을 하지 않았습니다.

실제 농업 자료 검토, Python 테스트 재실행, 실제 날씨·저장소·관측성·배포 검증은 남아 있습니다. P2인 일정 수정·삭제, 로그인, 사진 진단은 미구현입니다.
